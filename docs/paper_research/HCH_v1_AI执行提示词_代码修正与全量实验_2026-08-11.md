# HCH v1：代码修正与全量实验执行提示词

> 将本提示词完整交给代码 Agent 执行。目标是得到一版**无测试泄漏、方法集合固定、指标精简、覆盖全部现有数据集**的可信实验基线。不要在本轮扩展创新点或重构仓库。

## 一、任务目标

在仓库 `https://github.com/disdorqin/bech-paper` 当前结构上完成三件事：

1. 修复现有实验流程中的数据切分、阈值、随机种子、结果保存等问题。
2. 使用锁定的方法集合，在仓库当前支持的**全部数据集 × 全部现有宿主模型**上运行完整实验。
3. 生成可审计的 JSON、CSV 和简洁 Markdown 报告，并同步到当前 GitHub 仓库分支。

本轮是第一版干净基准，不追求新增模块或最终 SOTA。

## 二、禁止改变的内容

### 2.1 仓库与算法

- 保持现有 `data / docs / experiments / paper / src` 结构，不新建复杂架构。
- 不引入 adaptive low/normal/high、动态图、共形新模块或其他创新设计。
- 不改变 HCH 的核心数学形式和默认算法配置；只修复实验规范、接口和明显代码错误。
- 不使用 S4 调参、选择阈值、早停、拟合、标定或决定是否启用分支。

### 2.2 方法集合锁定

**Base 只是原始预测参照，不计入五个同行基线。五个同行基线不新增、不删除、不替换：**

1. `quantile` / QuantileCorrection
2. `vahedi` / VahediStyle
3. `spike_reg` / SpikeRegularization
4. `crc` / CRC
5. `delta_adapter` / DeltaAdapter

另外保留：

- `identity` / Base：冻结宿主原始预测。
- `HCH`：ours。

本轮不得用 PIR、Residual-L1 或其他方法替换上述五个。可以修复这五个方法的统一调用、数据切分和结果输出，但不要重写其核心算法。报告中为每个方法保留 `implementation_note`，如属于当前仓库代理实现，应如实标注，不要虚称官方复现。

## 三、必须修复的代码问题

### 3.1 严格时间切分

保留仓库当前的按比例时间划分；默认可使用 `S1/S2/S3/S4 = 50%/20%/10%/20%`，不要求所有数据集固定一年测试。

数据只能按以下方向流动：

- S1：宿主训练与冻结；计算并冻结事件阈值。
- S2：HCH 和五个同行方法的训练/拟合。
- S3：仅供需要标定或选择配置的方法使用。
- S4：只允许一次最终预测和评估。

删除当前 `corr_full = S2+S3+S4` 后再切 75% 的做法。增加硬断言：

- 四段索引严格递增、互不重叠。
- 任何 `fit/calibrate/select` 接口不得收到 S4 索引。
- 所有方法在同一数据集和宿主下共享完全相同的 S1–S4。
- 若断言失败，立即停止该组合并记录错误，不得继续生成“成功”结果。

### 3.2 事件阈值统一

- 物理负价阈值固定为 `negative_thr = 0`。
- 正尖峰阈值使用 S1 真值的 `p99`，计算一次后冻结。
- S2、S3、S4 训练、路由和评估必须使用同一正尖峰阈值。
- 禁止在 S4 真值上重新计算 p99。
- 每条结果必须保存 `negative_thr`、`spike_thr` 及其来源段。

### 3.3 runner 统一

- 让 Base、五个同行基线和 HCH 共用同一个数据入口、宿主预测、切分和评估函数。
- `--dataset all` 必须覆盖仓库当前注册的全部公开数据集，并额外包含 `shandong`；不得静默漏跑。
- `--backbone all` 覆盖当前 `BACKBONES` 中的全部宿主，不新增宿主。
- 同一数据集×宿主的原始预测只生成一次，随后供全部方法复用。
- 方法失败时记录 `status=failed` 和完整错误原因，其余组合继续运行。

### 3.4 可复现性与安全检查

- 第一版全矩阵统一使用固定 `seed=0`。
- 删除依赖 Python 进程随机化的 `hash(dataset+backbone)`；改为稳定 seed。
- 实际调用已有 `assert_no_leakage`。
- 记录代码 commit、参数、数据长度、S1–S4 时间范围和样本数。

## 四、第一版精简指标

所有方法使用完全相同的指标函数。只保留以下诊断第一版所必需的指标：

### 4.1 总体预测

- `MAE`
- `RMSE`
- `rMAE`：使用 S4 同期的 `t-168h` 周季节朴素预测作为分母

### 4.2 负价与正尖峰

负尾：

- `neg_n`
- `mae_on_neg`
- `neg_miss_rate`

正尾：

- `spike_n`
- `mae_on_spike`
- `spike_miss_rate`

### 4.3 正常期与动作量

- `normal_n`
- `mae_on_normal`
- `touch_rate`：预测值被方法实际改变的比例

报告中再计算每个方法相对 Base 的：

- 总体 `Delta-MAE`
- `Delta-MAE-on-neg`
- `Delta-MAE-on-spike`
- `Delta-MAE-on-normal`

若某数据集没有负价或没有对应尾部事件，必须输出 `event_n=0`、指标为 `null`，不能写成 0，也不能借用 S4 调整阈值。本轮暂不加入 PR-AUC、F1、episode、经济收益、NDR、q95 harm 等扩展指标。

## 五、执行流程

1. 先阅读 `AGENTS.md`、主 runner、peer runner、HCH、公共切分与指标代码。
2. 在修改前记录当前 `git status`，保留用户已有的无关改动。
3. 完成最小代码修复，不做目录重构。
4. 运行自动检查：索引互斥、S4 不进入训练/标定、阈值只来自 S1、固定 seed、rMAE 可计算。
5. 先做一个数据集×一个宿主×全部七条方法的 smoke test。
6. smoke test 通过后，运行：
   - 全部现有数据集，包括 `shandong`；
   - 全部当前宿主模型；
   - Base + 五个锁定同行基线 + HCH；
   - 固定 `seed=0`。
7. 不得只挑成功或效果好的组合。失败组合也必须进入结果清单。
8. 全量运行结束后检查任务数：`数据集数 × 宿主数 × 7` 必须与成功数和失败数之和一致。

## 六、必须产出的文件

在现有实验结果目录中使用**全新且带时间戳的文件名**，不得覆盖旧结果：

- `v1_full_matrix_<timestamp>.json`：完整机器可读结果与配置。
- `v1_full_matrix_<timestamp>.csv`：每行一个数据集×宿主×方法。
- `v1_full_report_<timestamp>.md`：简洁实验报告。
- `v1_full_failures_<timestamp>.log`：失败组合、堆栈和处理情况；无失败也生成并写明 `0 failures`。

Markdown 报告只包含：

1. 实际运行的方法、数据集、宿主、seed 和切分规则。
2. 总任务数、成功数、失败数。
3. 各方法相对 Base 的总体、负尾、正尾、正常期变化。
4. HCH 在哪些数据集有效、恒等、退化，以及原因是否能由事件数和 touch rate 解释。
5. 五个同行基线与 HCH 的排名；不做创新性讨论。
6. 下一轮最值得修的 3–5 个算法问题，只依据本轮干净结果，不提出未经实验支持的新模块。

## 七、验收条件

只有同时满足以下条件才算完成：

- S4 从未进入任何方法的训练、选择或标定。
- 正尖峰阈值只由 S1 得到，评估不再使用 S4 p99。
- 五个同行基线保持不变，Base 与 HCH 均在同一 runner 中。
- 所有现有数据集和宿主都有成功记录或明确失败记录。
- 所有方法共享同一宿主预测、切分、阈值和指标。
- JSON、CSV、MD、LOG 数量与内容相互一致，旧结果未被覆盖。
- 报告能明确区分“无事件导致不适用”“主动 abstain”“发生退化”和“运行失败”。

## 八、同步仓库与最终汇报

完成后：

1. 检查 `git diff`，只提交本任务相关代码、配置和结果报告，不碰无关文件。
2. 使用清晰 commit，例如：`fix: isolate v1 evaluation and run full benchmark`。
3. 在已有权限时推送当前工作分支；若无法推送，明确报告原因，不要伪称成功。
4. 最终回复必须给出：
   - commit hash 与分支；
   - 修改文件清单；
   - 全量实验命令；
   - 成功/失败任务数；
   - 四个结果文件路径；
   - HCH 最主要的 3–5 个实验发现。

不要只汇报“代码已完成”；必须完成全量实验和结果审计后再结束任务。
