## 2. 当前代码事实，不得按理想架构臆测

当前代码采用四段 rolling-origin：

- S1 50%：训练并冻结基座；
- S2 20%：训练负价/正尖峰 occurrence heads 与条件幅值 heads，并选择部分门控参数；
- S3 10%：在 lambda 网格上计算 moving-block bootstrap gain LCB 与 harm 分位数，选择 lambda；
- S4 20%：一次性测试，仅报告 S4。

当前校正形式为

\[
\widehat y_t^{\mathrm{BECH}}
=\widehat y_t^0+\lambda_b\widehat\delta_{t,b}
\mathbf 1\{\widehat p_{t,b}>\tau_b,\ b=\arg\max_k\widehat p_{t,k}\},
\]

其中 \(b\in\{-,+\}\)。若分支不存在、样本不足或没有正的 \(\lambda\) 通过门禁，则 \(\lambda_b=0\)，预测与基座 bit-exact 相同。

对候选动作定义绝对误差伤害

\[
H_t(a)=\ell(y_t,\widehat y_t^a)-\ell(y_t,\widehat y_t^0),
\qquad \ell(y,\widehat y)=|y-\widehat y|.
\]

当前 S3 对每个 lambda 同时做：

1. 在 routed 样本上计算 harm 的经验上分位数；
2. 在全 S3 小时的 gain 序列上计算 moving-block bootstrap LCB；
3. 从可行 lambda 中选择 LCB 最大者。

这意味着“用同一 S3 选择 lambda，再用 S3 为被选 lambda 发证书”，可能存在 selection/multiple-comparison validity 问题。请不要忽略它。

当前实证事实：45 个公开数据集×基座组合中 16 个激活、29 个弃权；所有激活均来自负价分支，正尖峰分支全部弃权。当前主矩阵有一个 `NEM_VIC1/Transformer` 小幅 S4 退化（MAE gain 约 -0.239%，不显著），而同行对照文件中的 M7 在 18 个组合上为 0 次退化。结果版本需要统一，因此不能把“所有测试组合零退化”当作数学前提。

## 3. 任务 A：设计真正成立的数学基础

请给出一套可以直接写入 Method/Theory 的数学方案。每一项必须包含：正式定义、假设、命题/定理、证明或证明纲要、不能保证的边界、与当前代码的差异。

### A1. 信息集与无 oracle 定义

定义日前信息集 \(\mathcal I_t\)，明确 \(\widehat y_t^0\)、日历、日前外生预测、至少滞后 24h 的真实价格/残差属于哪个信息集。证明路由动作 \(A_t\) 对 \(\mathcal I_t\) 可测，真实事件标签 \(G_t\) 和 \(y_t\) 在运行时不可见。

必须区分：

- 价格事件：\(G_t^- = \mathbf 1\{y_t<0\}\)、\(G_t^+ = \mathbf 1\{y_t>q_{0.99}^{S1}\}\)；
- 预测路由：由 \(\widehat p_{t,-},\widehat p_{t,+}\) 决定；
- 残差方向：\(\operatorname{sign}(y_t-\widehat y_t^0)\)。

三者不得混同。

### A2. 风险对象必须唯一且可解释

请比较并选择一个主风险对象：

1. predicted-route conditional risk；
2. true-event-group conditional risk；
3. action-conditional risk；
4. normal/negative/positive 三组的 base-relative expected harm、VaR、CVaR 或 exceedance probability。

说明为什么选择它、运行时是否可实现、认证样本如何分组、稀有组如何处理。给出正常组、负价组和正尖峰组的预算 \(\varepsilon_0,\varepsilon_-,\varepsilon_+\)，并说明哪些预算可以设为 0。

“zero degradation”只能用于：

- \(\lambda=0\) 的恒等动作；或
- 确有定理支持 \(\varepsilon_g=0\) 的指定风险量。

其他情况统一称为 `budgeted harm`，不能写逐未来样本必然不劣。

### A3. SCARR 两层证书

请判断以下两层能否形成一个联合定理：

- efficacy：总体或分组平均 gain 的 moving-block bootstrap lower confidence bound 大于 0；
- safety：harm 的 conformal upper quantile 不超过预注册预算。

必须回答：

1. 时序相关下需要 exchangeability、block exchangeability、mixing 还是 stationarity 假设？
2. moving-block bootstrap LCB 能给什么渐近或有限样本结论？
3. split conformal 在当前时间序列协议下能给什么覆盖结论？
4. 两层同时通过时，联合失败概率如何分配？
5. 对负、正两个分支和 lambda 网格搜索，如何处理 multiple testing/model selection？
6. 证书是边际、条件、近似条件还是经验认证？禁止使用不成立的“无条件 distribution-free”措辞。

### A4. 四段还是五段

请比较以下两个合法方案，而不是直接要求增加一段：

- 方案 F4：保留四段，但用预注册 lambda、uniform confidence bound、Bonferroni/Holm、nested conformal、cross-fitting 或其他方法，使 S3 的选择与认证仍有效；
- 方案 F5：S1 base fit / S2 head fit / S3 policy select / S4 certify / S5 final test，给出推荐比例及稀有事件功效损失。

请给出最终推荐，以及“最小代码改动方案”和“理论最干净方案”。本项目 CPU only，不能用大量重复训练掩盖协议问题。

### A5. 可预测性驱动的不对称

当前用 AUC/AP 判断尾部分支是否值得修正，容易被评价为 heuristic。请设计更严格的选择规则，例如：

- 相对常数分类器/基准发生率的 AP improvement；
- 带置信区间的可预测性检验；
- 直接以认证可行集非空作为分支类型选择；
- 将 predictive utility 与 correction utility 连接的 regret/risk 命题。

请判断是否有必要把 AUC/AP 写进算法，还是只把它作为机制解释，真正的分支选择完全交给风险证书。

### A6. 最终理论交付格式

请输出：

1. 完整符号表；
2. 一个主定义、一个主定理、最多两个辅助命题；
3. 每个结论的假设和证明纲要；
4. 一段 reviewer-proof 的 guarantee wording；
5. 一张“数学对象 -> 代码变量/函数 -> 实验指标”对照表；
6. 哪些结论只是经验发现，不能包装成定理。

不要为了显得理论丰富而堆九个互不相连的公式。

## 4. 任务 B：确定最终 baseline

请将 baseline 分成 `必须实现`、`条件允许实现`、`仅 Related Work 引用` 三档，并说明每一个 baseline 排除哪种替代解释。

### B1. 直接竞品：后处理/安全校正

候选至少包括：

- frozen base（恒等参考）；
- global residual L2/L1 adapter；
- calibrated shrinkage residual adapter；
- quantile post-processing；
- EVT tail rescaling；
- selective correction without certificate；
- delta-Adapter（必须按原论文实现核对，不能把普通 LightGBM residual learner直接冒充官方方法）；
- CRC；
- COSA/PIR，以及 reviewer 指出的最新 action-conditional risk 方法；
- 一个与主定理同风险对象的 conformal/CRC baseline。

请逐项判断：是否有官方代码、是否能公平适配点预测、是否要求额外输入、CPU 成本、无法复现时可接受的简化版本。CRC 是最贴近的方法，原则上不能只引用不实验。

### B2. 冻结基座：模型无关性而非 SOTA 排行榜

现有 Linear/MLP/LSTM/lightweight Transformer/LightGBM 可用于异构误差结构，但不能代表 SOTA。请判断最小充分基座组合：

- 强线性电价基线：LEAR/ARX 或 DLinear；
- 强树模型：LightGBM；
- 序列深度模型：LSTM；
- 至少一个官方实现的现代模型：PatchTST、TimesNet、TimeMixer 中选 1--2 个。

请按“审稿收益 / CPU 成本”排序。回答是否真的需要 PatchTST + TimesNet + TimeMixer 三个都跑，还是一个官方现代模型加三类传统异构基座已经足够。

### B3. baseline 最终交付

输出一张表：方法、类别、原始论文、官方代码、输入公平性、所需切分、主要指标、实现优先级、预计 CPU 成本、若缺失会遭遇的审稿质疑。

6. 阴性对照需要几个？GEFCom 与 Nord Pool 是否重复？
7. 数据集选择是否会产生 cherry-picking？请设计预注册纳入/排除规则。

### C3. 推荐矩阵格式

请输出：

- `核心主表`：语义一致、直接验证主要 claim；
- `外部效度`：市场机制或预测任务不同，但验证模型无关性；
- `阴性对照`：无负价/极端样本不足，验证合理弃权；
- `内部补充`：山东；
- `删除`：不能提供独立证据或任务语义不清的数据。
