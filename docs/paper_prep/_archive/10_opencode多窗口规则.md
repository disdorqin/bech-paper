# 10 · opencode 多窗口协作规则

> 生成：2026-08-07 ｜ 总指挥：claude_code
> 背景：用户开了 3 个 opencode 窗口。claude_code 是总指挥（核心设计/分发/验收），opencode 窗口是执行者（检索/实验/审计）。

---

## 0. 为什么必须标记窗口

AI Memory 的 agent 心跳按 **agent 名** 注册。三个窗口若都叫 `opencode`：
- agent_list 只会显示一个（互相覆盖）；
- task claim 无法区分谁领了任务（歧义）；
- 上报通道（agent_send→opencode）会发到"最新心跳的那个窗口"，不可控。

**解法：每个窗口一个唯一窗口名，心跳/上报/claim 都用这个名。**

---

## 1. 窗口命名（标记）

| 窗口 | 唯一名（agent 名） | 建议驻留 |
|---|---|---|
| opencode 窗口 1 | `opencode-b1` | BECH 项目，主执行（检索/审计/实验） |
| opencode 窗口 2 | `opencode-b2` | BECH 项目，副执行（消融/对比实验） |
| opencode 窗口 3 | `opencode-b3` | BECH 项目，备用/并行检索 |

> 若某窗口主要做别的项目（如 math_model_ai_process），另行命名，不占用 b1-b3。

**每个窗口启动时**：
1. 用唯一名跑心跳（`agent_heartbeat(agent=自己的窗口名)`）；
2. 告诉 claude_code 你的窗口名（agent_send 到 claude_code）；
3. 查任务单 `task_list(agent=自己的窗口名)`，claim 派给自己的任务；
4. 上报用 `task_submit(agent=自己的窗口名)`。

---

## 2. 协作规则

1. **任务单为准**：只做 `assigned_to=你的窗口名` 的任务；不 claim 别人的。
2. **深度思考模式（强制）**：每条结论给依据（原文页码/章节/数据来源）；主动自我反驳（结论前先列可能错的 3 个理由并回应）；区分「原文明确写了」与「我的推断」两栏。
3. **单任务串行**：一个任务 claim 后做完再 claim 下一个；任务做完 task_submit 并回报。
4. **产出进 docs/paper_prep/**：检索/审计/实验文档命名 `NN_主题.md`，避免与已有冲突。
5. **读项目规则**：仓库根 `AGENTS.md`；研究现状 `docs/paper_prep/00-09*.md`；深读笔记在 load_forecast 的 papers/field/。
6. **环境**：CPU only，conda epf-2 = `D:/computer_download/environment/conda/epf-2/python.exe`。
7. **关键原则**：山东数据绝不进论文；负价漏判率按事件数加权；不宣称被占据的禁区（见 09 框架与 06 划界）。

### 2.1 派单纪律（总指挥 claude_code 责任）【2026-08-07 事故后新增】

> 事故复盘：tcc84b259 派给 b3，但 b3 从未在线 → 任务卡 pending，b1 完成产物却因归属不符无法 claim/submit → b1/b2 互发转派请求互相干扰。

1. **派单前必查在线状态**：总指挥用 `agent_list` 确认窗口心跳，只派给**确认在线**的窗口；不在线的窗口宁可等、不派。
2. **一单一人**：一个任务只建一张单、只指派一个窗口；不建"可 b1 或 b2 接"的模糊单。
3. **归属即铁律**：任务单 `assigned_to` 写谁，就只能谁 claim/submit；任何人发现归属与自己不符→**停止动作，agent_send 请示 claude_code**，不自行互转、不代提交、不抢单。
4. **掉线兜底**：若窗口掉线导致任务悬空，总指挥新建同内容任务单转派在线窗口，原单标注作废；执行者不自行改单。
5. **产物编号预留**：任务单里写明产出文档编号（如 `12_xxx.md`），避免两窗口抢同一编号。

### 2.2 上报纪律（执行者责任）【2026-08-07 事故后新增】

1. **完成只向总指挥上报**：`task_submit(agent=你的窗口名)` + `agent_send(to=claude_code)`。**禁止**向 b1/b2/b3/其他窗口互发"完成/转派/代提交/确认"消息。
2. **窗口间只允许被动查询**：如需了解他人状态，用 `agent_list`/`task_list` 只读查询，不主动发消息给对方。
3. **产物以文档为准**：完成结论写进 docs/paper_prep/NN_文档，上报只报"文档路径+3-5 条要点+待决问题"，不在消息里长篇复制正文。
4. **不重复上报**：一个任务只 submit 一次；若总指挥已验收，不重复催。
