## 0. 用户的原始直觉（逐句翻译）

用户原话："结合输入数据（无论特征多少）都会在第一部分自动建立，比如 MLP 可以将低维数据映射到高维，自动构建大量的/残差/分解分量什么的衍生特征，只不过我们用图结构……这个 idea 还不太成形，不知道怎么表达。"

拆成三个成分：
1. **任意输入 → 自动构建丰富衍生特征**（不依赖市场特定特征工程）
2. **MLP 低维→高维 = 自动学特征**（用户举的例子，说明"自动构建"机制）
3. **用图结构做这个构建**（"只不过我们用图结构"——用户想要的终极形态）

**用户想要的东西，一句话成形**：一个**图结构特征合成器**——校正模块的第一层，把任意原始输入（预测值 + 任何可用特征）自动组织成一张"特征关系图"，用 GNN 在图上做消息传递，自动合成高阶衍生特征，再交给双尾事件感应器和条件校正头。

## 1. 一个必须先厘清的关键区分（决定设计走向）

用户的直觉里混了两个"自动生成特征"，它们完全不同，必须分开：

| | 隐式特征学习 | 显式特征构造 |
|---|---|---|
| 机制 | MLP/GNN 隐藏层自动学表示 | 规则/算法显式生成可解释特征 |
| 例子 | MLP 把 yhat 映射到 128 维 | 残差 lag24、STL 分解的趋势/季节/残差、日内形状 |
| 可解释性 | ❌ 黑箱，审稿人不买账 | ✅ 每条特征有名字有含义 |
| 谁在做 | 神经网络 | 特征工程 / 信号分解算法 |
| 现状 | BECH 幅度头已是 MLP（隐式） | 07 文档轨道 A 的规则特征（显式，手工枚举） |

**关键认识**：MLP "自动构建大量特征" 生成的是**隐式黑箱特征**，它不能"凭空生成残差分量/分解分量"这种**显式可解释特征**——那是算法规则做的。所以用户的 idea 要成立，得明确一个分工：

- **显式衍生特征**：仍由规则层构造（残差历史、分解、日内形状）——这是 07 文档轨道 A，已经做了，不需要 MLP。
- **图结构的角色**：不是"生成特征"，而是**组织已有特征 + 显式建模特征间的交互关系**——这才是图真正能做、而 MLP 做不好的事。

> **结论**：图的价值不在"自动生成特征"（MLP 也"生成"），而在**把特征之间的结构关系（相关性/因果/交互）显式建出来**。这正好呼应用户早先说过的"真实场景特征多、特征间有相关性、图可解释"。

## 2. 成形后的设计：GAFE（Graph-Adaptive Feature Encoder）

```
┌─────────────────────────────────────────────────────────────┐
│  任意原始输入（轨道A最小契约 或 轨道B增强契约，特征多少都行）      │
│  yhat + 日历 + 残差历史 [+ fc_*/act_* 外生预报]                │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  GAFE 三层                                                │
│  L1 基础衍生特征层（显式，规则构造，可解释）                    │
│     残差lag24/48/168、滚动残差、STL分解分量、日内形状、          │
│     特征间差/比/归一化 —— 特征列越多自动生成越多显式衍生特征       │
│  L2 特征关系图构造（图的来源，关键）                          │
│     节点 = 每个（衍生）特征                                   │
│     边 = 统计先验：相关矩阵 top-k 稀疏化 / 格兰杰因果           │
│          （复用 06_NEM门禁 的方法论：相关+因果=边）             │
│  L3 GNN 消息传递（1-2层 GCN/GAT，图很小，CPU 可跑）            │
│     在特征图上聚合邻居 → 合成高阶交互特征 h ∈ ℝ^d              │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
              P(neg|Z) 感应器 / P(spike|Z) 感应器 / 条件幅度头
```

### 为什么这个设计成立

1. **任意特征多少都行**：L1 把任意输入转成"特征列集合"，特征多 → 节点多、图丰富；特征少（公开集）→ 节点少、图退化但仍有最小结构。**图自适应，不是固定图**。
2. **自动构建**：L1 显式衍生特征自动生成（越多特征输入，越多残差/分解/交互组合），L3 GNN 自动合成高阶表示。用户要的"自动构建"实现了。
3. **图可解释**：边来自**统计/因果先验**（相关矩阵 top-k、格兰杰因果），不是可学习黑箱邻接——每条边有语义（"残差lag24 与 日内形状 强相关"）。这正是防"图=换皮"的关键，也是用户要的"图可以解释"。
4. **与 07 契约天然衔接**：07 的轨道A/B 是 L1 的输入；GAFE 是 L1-L3 的神经化升级。自适应特征契约（07）是**输入层**的自适应，GAFE 是**特征构建层**的自适应，两层叠加。

## 3. 可行性判断（诚实版）

**结论：完全可实现，且规模很小，CPU 能跑。**

- **实现难度**：低-中。torch_geometric / DGL 或手写稀疏 GCN（图=特征数 20-60 个节点，一层消息传递）。无 GPU 压力。
- **图规模**：节点=特征数（几十），远小于时间序列图。训练快。
- **自建基座约束**：不冲突，GAFE 在 S2 段训练（与校正头同段），五段防泄漏协议不变。

**两个必须提前认识的风险（写论文前要想清楚）**：

| 风险 | 说明 | 对策 |
|---|---|---|
| ① "图在特征上" vs "图在通道上"的混淆 | 文献里的时空图（MTGNN/StemGNN）节点=时间序列**通道**，边=通道相关性，GNN 跨时间消息传递；BECH 输入是**单变量预测+特征**（每时刻一个特征向量），不是多通道。若把 GAFE 说成"时空图"，会被批"输入都不一样"。 | 定位必须准确：GAFE 是**特征关系图**（节点=特征），不是时空图（节点=通道）。Related Work 与表述都要钉死这一点。 |
| ② 图增益是否真的大于 MLP 隐式特征 | GAFE 与纯 MLP 幅度头比，增量来自"显式特征交互"。若增量不显著，图就是白加复杂度。 | 必须做公平对比：同参数量、同种子，MLP-vs-GAFE-vs-MLP+图。这正是用户之前强调的"控制参数量、训练量、种子公平"。 |

## 4. 与三个已有卖点的合并（论文故事）

GAFE 不是第四个独立卖点，而是把已有设计串成一个完整故事：

| 层 | 卖点 | 文档 |
|---|---|---|
| 输入契约 | 自适应特征契约（轨道A最小/B增强）——**按可用性自适应** | 07 |
| 特征构建 | **GAFE 图结构特征合成器**——按特征丰富度自适应建图 | 本文件 |
| 事件识别 | 双尾感应器 P(neg)/P(spike)（负价专用 + 正尖峰弃权） | 05 |
| 校正 + 认证 | 条件幅度头 + SCARR 三层证书 + 未认证弃权 | 05 |
| 价值 | 经济价值认证（储能利润/CVaR） | 05 |

> **叙事一句话**：BECH 是一个**结构自适应的极端电价校正头**——输入契约按数据可用性自适应（07）、特征按丰富度自适应构建关系图（GAFE）、校正动作按 tail-conditional 认证自适应触发（SCARR）。三层自适应贯穿"输入→特征→动作"。
